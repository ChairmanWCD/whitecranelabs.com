01 — The brief

Two models, one Mac

Creative teams need to generate and edit images. Cloud APIs make that easy — until you hit cost, latency, data privacy, and shared-queue waits at scale. Every generation is metered, every prompt leaves the machine.

Running open-weight models locally solves that — but now you need two engines: text-to-image for creation and image-to-image for edits. On Apple Silicon that means fitting ~60 GB of weights and two pipelines into 32 GB of unified memory.

The question wasn't "can we run a diffusion model?" It was: "Can a single Mac — the machine a studio already owns — become a serious, always-on studio for both generation and editing?"

White Crane Studio says yes — a FAL.ai-style server with Z-Image-Turbo for T2I and FLUX.2 Klein 9B for I2I, with ComfyUI-like swapping so only one engine is resident at a time.

03 — The architecture

A FAL.ai-style async queue

Generation is slow. UI's must never wait on it. The core design mirrors FAL.ai's pattern: submit a job, poll for status, fetch the result. The interface stays instant while a background worker owns the heavy inference.

Submit, poll, fetch. The UI never blocks on a generation.

Async flow
POST /submit → returns a request_id · GET /status/{id} → IN_QUEUE / IN_PROGRESS / COMPLETED · GET /result/{id} → the images, seed, and timings.

Two APIs, two engines — one facade

  • Async queue API — /submit → /status → /result, plus /cancel. Built for polling clients and parallel workloads.
  • Sync API — POST /generate returns the result inline, with sync_mode for base64 data URIs.
  • Support endpoints — /health (checks both engines), /api/history (recent images), /output/{file} (static files), Swagger at /docs.
  • ZStudio facade — app.py:377 routes by input: no image → Z-Image-Turbo T2I; with image (base64 data URI) → FLUX.2 Klein 9B I2I. _ensure() swaps the inactive pipeline to cpu + torch.mps.empty_cache() so only one is resident.

An eager warmup at startup — Z-Image warm, then Klein probe (512×512, 2 steps) — pays the cold-start cost once so the first real request is fast. Queue depth is capped (MAX_QUEUE_SIZE), failed jobs retry, and completed results expire after a TTL.

04 — The hard problem

Fitting ~60 GB and two pipelines into 32 GB unified memory

White Crane Studio is heavy by design: Z-Image-Turbo is ~20.7 GB local, FLUX.2 Klein 9B is ~40 GB auto-downloaded, and together they need two full pipelines. On a 32 GB M4 nothing can stay resident at once — so the design treats memory as a rotating resource and dtype as a correctness choice.

How it stays under the ceiling

  • ComfyUI-like swap — ZStudio._ensure() offloads the inactive pipeline to cpu and calls torch.mps.empty_cache(); target loads to mps on demand.
  • bfloat16 on MPS — weights run in bfloat16 (~19.8 GB) — numerically stable on MPS with torch ≥2.13. float16 diverges to NaN/black at ≥1024.
  • Size snapping for Klein — reference image dims snapped to 32 px via _snap_size() between 256–2048; T2I presets are 768–1344 px. No large-request downscale hack — just honest swap.
05 — Native on Apple Silicon

From data-center Linux to python run.py on a Mac

The goal was no Docker, no CUDA, no duplicate installs — a plain Python process that runs on the Mac a studio already owns, sharing no assumptions with a data-center box.

  • No Docker — single process via python run.py (FastAPI + uvicorn on 0.0.0.0:8100), Ctrl+C to stop.
  • Local Z-Image weights — LOCAL_MODELS_DIR defaults to a sibling ../models; download_models.py fetches the 3 .safetensors files (resumable, ~20.7 GB).
  • Gated Klein 9B — auto-downloaded on first start via snapshot_download to ~/.cache/huggingface (~40 GB, resumable). Requires accepting the Flux license and HF_TOKEN in a local .env (gitignored).
  • MPS-native paths — config.py detects mps vs cpu (TORCH_DTYPE=bfloat16 default), binds HOST 0.0.0.0, and auto-detects LAN IP for result URLs.
  • Environment — PyTorch Apple Silicon build from PyPI (MPS), diffusers from git main, transformers ≥5.0, accelerate, vae subfolder fix for 16 latent channels.

One Mac. One command. Your own dual-engine studio.

06 — The interface

A studio-grade web UI

A server is only useful if people can drive it. The bundled single-page UI gives a full generation workspace with a dark, lavender-accented theme — and a light mode for bright studios.

  • Mode switch — Text to Image (Z-Image-Turbo) vs Image to Image (FLUX.2 Klein 9B badge) — output size follows preset for T2I, reference dims (snapped 32px) for I2I.
  • Prompt & reference — textarea with example chips, Cmd/Ctrl+Enter to generate; I2I dropzone with preview/remove for the reference image.
  • Size presets (T2I) — six aspect ratios from Square HD to Landscape 16:9.
  • Advanced settings — negative prompt, guidance scale (T2I; Klein fixed at 1.0), seed + randomize, inference steps (1–10; default 9 T2I, 4 Klein).
  • Live feedback — elapsed timer, skeleton loading, cancel, health status (z_image_turbo / flux2_klein), dark/light toggle (lavender), and a /api/history strip.

The API

Everything the UI does is also available over HTTP — a FAL.ai-style queue for async jobs, plus a synchronous endpoint for quick calls.

Async flow
POST /submit → request_id · GET /status/{id} → IN_QUEUE / IN_PROGRESS / COMPLETED / FAILED · GET /result/{id} → images, seed, timings.
  • Sync generation — POST /generate returns the result inline, with sync_mode for base64 data URIs.
  • Job control — POST /cancel/{id} cancels a queued job; completed jobs stay queryable until the result TTL expires.
  • Operational — GET /health checks readiness; GET /api/history lists recent images; GET /docs opens interactive Swagger docs.
  • Parameters — prompt (required), image_size (preset or custom), num_inference_steps (1–10), guidance_scale (0–20), negative_prompt, seed, num_images (1–4), output_format (PNG/JPEG).
07 — What's still hard

The tradeoffs

Local inferencing isn't a free lunch on Apple Silicon either. Being honest about the ceilings is part of the point.

01

Unified memory is a hard ceiling. Swap keeps you in 32 GB comfortably; drop to 24 GB and you lean harder on offload. Two engines resident at once would OOM — that's why swap exists.

02

Gated model friction. Klein 9B is gated on HuggingFace — you must accept the Flux license and set HF_TOKEN in .env, or that engine stays disabled (Z-Image still works).

03

bfloat16 vs float16. float16 on MPS diverges to NaN/black at ≥1024 — use the default bfloat16. If you override, keep sizes small.

04

MPS is slower than discrete CUDA. Expect 2–3× longer generation vs an NVIDIA card; warmup hides the first-hit cost but per-step throughput is lower.

08 — Why this matters

Generative infrastructure, owned

Serious creative tooling shouldn't require a cloud subscription. It should run on hardware a studio can actually afford.

White Crane Studio is proof that a Mac — not a lab, not a data center — can power a real, queue-based studio for both generation and editing. One command starts it, swap keeps it in memory, and prompts never leave the machine. No per-image fees. No vendor in between.
